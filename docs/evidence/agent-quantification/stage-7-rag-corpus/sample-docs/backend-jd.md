# 后端开发岗 JD 与能力要求

## 岗位定位

后端开发岗通常负责业务服务设计、接口开发、数据建模、性能优化、稳定性保障和线上问题处理。初中级岗位更关注基础编码能力、框架使用和问题闭环；高级岗位更关注系统设计、跨团队协作、容量规划、故障治理和技术取舍。

一个典型 Java 后端岗位会要求掌握 Java 基础、集合、并发、JVM、Spring Boot、数据库、缓存、消息队列、Linux 和常用工程工具。岗位描述中的“高并发”“分布式”“微服务”需要结合业务规模判断，不能只按关键词理解。

## 必备技术能力

Java 基础能力包括面向对象、异常处理、泛型、集合框架、Stream、反射和常用 IO。并发能力包括 synchronized、volatile、线程池、锁、原子类、并发容器和常见并发问题排查。JVM 能力包括内存区域、GC、类加载、OOM 排查和基本调优。

Spring 能力包括 IoC、AOP、事务、MVC 请求链路、配置管理和常见 starter 使用。数据库能力包括 SQL、索引、事务、锁、执行计划和慢查询优化。缓存能力包括 Redis 数据结构、过期策略、缓存一致性、穿透击穿雪崩和分布式锁。工程能力包括 Git、单元测试、日志、监控、灰度发布和问题复盘。

## 项目经验要求

JD 中的项目经验不只是“做过几个系统”。更有价值的是候选人能说明业务背景、个人职责、技术方案、上线结果和后续治理。比如订单系统、知识库系统、权限系统、工作流系统和数据同步系统，都可以体现后端能力，但必须讲清楚复杂度在哪里。

项目经验评价重点包括：是否做过完整需求闭环，是否处理过数据一致性问题，是否有性能优化证据，是否参与过线上故障排查，是否能说明技术选型理由。只写“参与开发”通常信息不足，应在简历和面试中补充具体贡献。

## 加分能力

加分项通常包括系统设计能力、云原生基础、消息队列经验、搜索或向量检索经验、可观测性建设、自动化测试和安全意识。对于 AI Agent 或 RAG 相关岗位，额外关注工具调用边界、Prompt 安全、检索评测、知识来源可解释性和外部内容注入风险。

加分能力要有证据支撑。比如写“熟悉 RAG”时，最好能说明文档解析、chunk 策略、embedding、vector store、topK、minScore、query rewrite、debug hit 和 eval set。只说“接入大模型接口”不能证明 RAG 能力。

## 面试关注点

面试官常用基础题确认候选人下限，用项目题确认真实经验，用系统设计题确认上限。基础题可能包括 HashMap、线程池、事务传播、索引失效和 Redis 缓存问题。项目题会追问“你负责哪一部分”“为什么这么设计”“上线后指标如何”“出现问题怎么回滚”。

系统设计题通常关注拆解能力。候选人需要先澄清需求，再给出核心模型、接口、存储、缓存、异步处理、限流降级、监控和扩展方案。回答过程中要主动说明取舍，例如一致性和性能、成本和可用性、开发速度和长期维护之间的平衡。

## 匹配判断

判断候选人与 JD 是否匹配，不能只看技术栈关键词。更可靠的方式是把岗位要求拆成能力项，例如 Java 基础、数据库、缓存、工程实践、系统设计、线上排障和业务理解，然后逐项寻找证据。证据可以来自项目经历、回答质量、代码样例、测试意识和复盘能力。

对初级候选人，可以接受系统设计经验较少，但要有扎实基础和学习能力。对高级候选人，不能只会写 CRUD，需要能处理复杂问题、指导方案落地并承担线上稳定性。JD 匹配最终应输出优势、风险和建议，而不是简单给出“合适”或“不合适”。
