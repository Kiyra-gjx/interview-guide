# S3-02：Context Assembly Policy

## 0. 任务状态

- 状态：未开始
- 当前定位：Stage 3 的上下文治理任务
- 前置依赖：S3-01 已完成或达到可消费状态

## 1. 任务目标

为单 Agent 建立统一、可解释、可控的上下文组装策略，让输入材料不再依赖临时拼接。

## 2. 要解决的问题

- 简历、知识库、历史记录、工具结果等上下文来源还没有统一装配规则
- token / 长度预算与裁剪优先级不清晰
- 同一类请求多次执行时，上下文构成容易漂移，导致输出不稳定

## 3. 本任务范围

- 上下文来源优先级
- 长度预算与裁剪规则
- 去重、冲突解决与降级策略
- Prompt / ToolContext 组装入口统一

## 4. 主要改动点

- `interview.guide.modules.agent.support.AgentToolContext`
- Prompt 组装相关服务
- session / turn 上下文拼装逻辑
- 与 context 相关的测试样例

## 5. 风险与边界

- 本任务不以新增工具为目标，而是治理已有上下文来源的组合方式
- 不把业务判断硬编码到 prompt 模板里，避免上下文策略不可复用
- 裁剪与优先级规则必须可解释，否则后续排障会很困难

## 6. 完成标准

- 同类输入在相同条件下能组装出稳定、可解释的上下文
- 上下文预算、来源优先级与降级策略都有清晰规则
- Tool、Prompt、Trace 对上下文内容的理解保持一致

## 7. 验证要求

- 至少覆盖多来源上下文拼装、预算裁剪、冲突去重三类测试
- 关键场景下可解释“哪些内容被带入，哪些被裁掉，为什么”
- 上下文策略变动后，可通过样例回归确认行为变化
