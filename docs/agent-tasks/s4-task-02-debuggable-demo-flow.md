# S4-02：Debuggable Demo Flow

## 0. 任务状态

- 状态：未开始
- 当前定位：Stage 4 的收口任务
- 前置依赖：S4-01 已完成

## 1. 任务目标

把已有能力组织成一条稳定、可调试、可展示的单 Agent Demo Flow，作为 Level A 的对外叙事收口。

## 2. 要解决的问题

- 即使工作台存在，仍可能缺少一条可重复演示的完整主流程
- 用户和开发者都需要知道系统何时成功、何时降级、何时失败，以及为什么
- 缺少为演示准备的状态切换、空态、失败态与说明材料

## 3. 本任务范围

- demo 主流程与入口状态设计
- 基于现有 `trace / memory / approval / toolOutput` 数据面的调试信息与演示视角统一
- 典型场景样例与演示说明
- 单 Agent 收口所需的异常态、空态、加载态整理

## 4. 主要改动点

- 前端主流程与状态切换
- 与 workbench 相关的 API / DTO 消费逻辑，尤其是统一 `toolOutput` 视图的展示组织
- demo 场景样例或文档
- 必要的说明文档与展示辅助内容

## 5. 风险与边界

- 本任务不进入多步 loop、planner 或 subagent 设计
- demo flow 要基于真实系统能力，不靠大量硬编码假数据撑叙事
- 不能为了演示效果牺牲调试真实性

## 6. 完成标准

- 至少有一条稳定可复现的单 Agent demo 主流程
- 用户能看懂一次执行为何成功、降级或失败
- Stage 4 完成后，项目可以作为完整单 Agent（Level A）对外说明

## 7. 验证要求

- 前端构建通过，关键 demo 路径可手工走通
- demo 场景覆盖成功、降级或失败中的至少两类状态
- 文档能说明如何启动 demo、如何观察执行过程、如何解释结果
